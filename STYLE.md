# isokit — Isometric Diagram Grammar

The authoritative rules for generating diagrams with this library. Written for both humans and AI agents authoring layouts. Corrections to visual output get ratcheted into this file — and into enforcement code in `src/isokit.ts` where possible — never applied as one-off fixes.

Authoring a diagram as YAML instead of a hand-written layout script? The format contract — keys, enums, derivation order, and the full error table — lives in [SPEC.md](SPEC.md); this document remains the underlying engine grammar for hand-authored TypeScript layouts.

## The target grammar

The style is the **Azure isometric blueprint / marketing style** (canonical references: SlideModel's Azure isometric sheet and Microsoft's 2015 Azure 3D blueprint art):

- Isometric projection on a gridded ground; components sit on the grid as extruded tiles/cubes.
- Tiers/zones as overlapping *translucent* planes — depth via stacked-glass layering, not borders.
- Zone boundaries as thin light diamond outlines; zone labels set along the iso axes.
- Flow arrows route along grid axes only (iso right angles), one hue per flow type.
- Numbered pointer chips in a single accent color keyed to a high-contrast legend rail *outside* the canvas — narrative lives in the rail, not in-diagram clutter.
- Restraint: roughly two grounds + white + one or two accents does everything.

## Machinery

The library is `src/isokit.ts` (projection, planes, flows, plates, glyphs, and shapes: box/slab/panel/cyl/rack/building/padlock/wall (brick firewall)/queue/store (layered blob/object storage)/browser/monitor/laptop/phone/person/personDevice/users). It is **themeable**: `THEMES` holds full token sets ("blueprint" dark-navy, "azure" marketing-blue with gold rims + pale-green flows); `setTheme(name)` swaps every token and rebuilds `GLYPHS`. Theme tokens are ESM live bindings, so import order relative to `setTheme()` does not matter (the Python prototype's from-import ordering gotcha is gone) — but isokit functions still must not use theme tokens as declaration-time default values (they freeze the theme; use null sentinels resolved at call time — shipped once). `plane(..., z=H)` floats a grouping sheet with dashed corner posts (reference-style raised tier).

New diagrams = a layout script using the **unit registry**: `unit(name, shapeFn, x, y, {...kw})` places components by name — positions **snap to the grid** (integer cell coords enforced with a hard error), every unit occupies a whole-cell footprint (default 2×2, `cells: [w, d]` overrides), the shape is auto-centered inside its cell block, and **overlapping footprints are a hard error** (touching edges are fine). `connect(a, b, {exit, enter, via: [...], style: "request"|"data"|"sync"})` draws flows by name — endpoints land on the cell rect, i.e. exactly on grid lines (`edgePt`, sides `"-x"/"+x"/"-y"/"+y"` with an optional `t` along the edge, auto-picked from the dominant center delta when omitted), with a machine-routed detour when no `via` is given (see the auto-routing rule below) and the in-plane arrowhead computed; `renderUnits()` emits everything in painter's order. Mermaid's connect-by-name ergonomics with grid-snapped positioning, no string DSL — layouts stay plain TypeScript.

Flow semantics follow the reference's two-weight system: solid single-head = request/control (`style="request"`), thin double-headed = bidirectional control (`style="sync"`), dashed with origin dot = data run (`style="data"`).

Exemplar layouts: `layouts/azure_lob.ts` (Blueprint theme, gold standard), `layouts/hybrid_onprem_azure.ts` (Azure theme, hybrid on-prem topology, estates as the network boundary), `layouts/components.ts` (full shape vocabulary).

## Projection model

Grid coords (x right-down, y left-down, z up); `X = OX + (x−y)·0.866·U`, `Y = OY + (x+y)·0.5·U − z·U`. Plane-lying text/glyphs use full affine shears:

- ground/top plane, baseline along +x: `matrix(0.866, 0.5, -0.866, 0.5, X, Y)`
- ground plane, baseline along −y: `matrix(0.866, -0.5, 0.866, 0.5, X, Y)`
- SW face (no mirror): `matrix(0.866, 0.5, 0, 1, X, Y)`
- SE face (mirrored basis, rects only): `matrix(-0.866, 0.5, 0, 1, X, Y)`

## Hard-won rules

- Plane-lying text needs the full affine shear, NOT a screen rotation.
- With this projection, the **visible faces of an iso cube are top + y-max + x-max**. Drawing a min-coordinate (back) face instead produces an L-shaped shell that reads as a hollow "L platform" — units must be closed solids (shipped once).
- Iso cylinder ellipse: `rx = 1.2247·r·U`, `ry = 0.577·rx` (tan 30°) — halving ry looks subtly squashed.
- Arrowheads must lie **in the ground plane**: build the head as a grid-space triangle at the flow's end (tip on the target edge, base at tip−dir·0.42, half-width 0.21), project through `iso()`, and shorten the shaft to the head base. SVG `marker` elements are screen-space and always look wrong.
- Icon decal on a cube's y-max face: `<g transform="matrix(0.866,0.5,0,1,Tx,Ty)">` anchored at `iso(x, y+s, h)`. The x-max face would need a mirrored basis — use the y-max face for glyphs.
- **Shape anatomy:** solids are LIGHT gray (near-white top, mid SW, darker SE) with the role-colored rim stroking the *top face only* — dark solids read as generic boxes, light-with-rim reads as Azure. Shape marks are flat dark glyphs drawn ON the shape, never full-color product icons pasted on faces — those read as stickers. Cylinder: gradient body, thick rim ring, ~square silhouette (r=0.5, h=1.25 tiles). Devices are real shapes (laptop = base slab + tilted screen slab; phone = thin upright slab); people = flat light-ink silhouettes. Glyphs must survive the shear at face size — use bold strokes (≥3.5 in a 40-box) and big heads; thin zigzags turn to scribble.
- Text/labels on a shape face must be projected into the surface, never left screen-flat. On a **curved** surface a single flat shear is also wrong: wrap it per-glyph. Cylinder recipe: glyph i at azimuth `t` (t=0 faces viewer), screen anchor `(Xc + rx·sin t, Yc0 + ry·cos t)`, transform `matrix(cos t, −(ry/rx)·sin t, 0, 1, X, Y)`; advance per char along the surface = `font-size·0.6` (JetBrains Mono); center the run at `t = −π/4`, the azimuth whose tangent equals the SW-face shear — so cylinder labels face SW like every box-face glyph. `t = 0` reads as inconsistent; an arbitrary off-center t reads as left-aligned.
- Ground grid lines must survive the translucent grouping planes laid over them: line opacity 0.22 (0.12 vanished under a 0.07 plane fill). The ground can carry two-tone **estates** — zones split by a boundary on a grid line (`grid({seam: ["x"|"y", coord]})`); the boundary coordinate must be an **integer** so the edge lands exactly on a grid line — enforced with a hard error.
- Chips and legend come from ONE declaration: `annotate(unit, title, desc, approach?)` once per unit, then `annotations({footer})` emits every chip AND the legend rail, numbered in declaration order. The approach point is optional — omit it in the common case and the renderer picks a clear side automatically (see the auto-approach rule below); author it only for craft placements. Never author chip numbers or legend entries separately — desync is silent. Unknown unit or double annotation is a hard error.
- Legend rails come from `legend(entries, {footer})` (used by `annotations()`; direct use only for non-unit entries), never hand-rolled: it owns spacing metrics, wraps descriptions, and checks content extent against the canvas height captured by `svgOpen()` — overflow is a hard error instead of a silent clip.
- Flows are axis-locked and `flow()` enforces it: every segment (including `via` waypoints) must run along exactly one grid axis or it is a hard error. A grid diagonal renders at a non-isometric screen angle (a `(1,−1)` diagonal comes out screen-horizontal) and breaks the projection illusion.
- Units snap to the grid — integer cell coordinates, whole-cell footprints (default 2×2, `cells: [w, d]` for bigger shapes), shape auto-centered in its block. Overlapping footprints are a hard error (touching edges are fine). Flow endpoints computed from the cell rect land exactly on grid lines.
- Numbered chips are pointers, not dots: `chip(n, x, y, to="unit")` (authored via `annotate()`, not called directly) draws a pin tail aimed at the unit. The authored position sets only the approach direction — the chip auto-slides along that ray so the tip stops a consistent 5px off the unit's **body silhouette** (the solid alone: footprint corners at ground and declared height, or a declared tighter `body` — cyl's drum, wall's brick slab, users' person+laptop+phone ensemble; any shape drawing solids inset in its footprint must declare one, or chip tips stop at the footprint's phantom air — hybrid's chip 3 floated ~27px short of the firewall bricks, and the group pack demo's chip 1 floated ~26px west of the person). NOT the plate-inclusive collision hull: that hull's side edges slant out to the plate's ground corners, and a tip stopped off the slant floats in mid-height air — a tall building shipped hybrid's chip 1 pointing at the estate boundary ~26px off the tower wall (worsened by the building's undeclared 1.1 footprint: the registry hulled a phantom 1.4 — shapes with a non-1.4 default `s` must declare `defS`). Author the approach from a side clear of *other* units, flows, and labels; the snap only knows the target's body, and a drum-snapped chip can slide onto a label lying beside the cylinder. Numbers render well 0–9999: one digit keeps the r=11 circle; more digits widen it into a horizontal pill (same 22px height), never a bigger circle. The pill grows *away* from the target so the tail tip never moves with digit count (bare chips stay centered on their point); legend number bubbles grow left from a fixed right edge so the gap to the vertically-aligned text column is constant.
- Draw units in painter's order sorted by `x+y`; route flow lanes and place labels clear of cube *screen projections* (tops occlude far more than their footprint).
- SE-face decals (rack fins, building windows) use the mirrored basis anchored at `iso(x+s, y, h)` — local x stays POSITIVE; negating it detaches the decal into mid-air (shipped once). Text can't use this face (it would mirror); rects are fine. Each face's pattern must be sized to **that face's own width** — reusing the long face's width on a narrow end face spills strays past the silhouette (firewall bricks shipped this way once).
- Fake extrusion for in-plane stroked shapes (padlock shackle, any bar/pipe/arc): sweep the same path in dense steps (~11) along the screen-projected normal offset `(-0.866·t·U, 0.5·t·U)` in a mid tone, then a dark back-edge pass and a lighter front-face pass. A single flat stroke reads as 2D; coarse steps read as comb teeth. Anything mounted on another solid draws AFTER the body if it lives entirely above it, with contact points landing visibly on the face.
- Shape collision properties are **declared on the shape function**, never derived from `fn.name` (name lookups break under minification and force engine edits per shape): `Object.assign(myShape, { defH: 1.2 })` sets the typical silhouette height (`kw.h` overrides per unit; 1.0 if undeclared), and an optional `hull: (x, y, s, kw) => Pt[]` returns a screen hull tighter than the footprint box — only needed when the shape is much slimmer than its cells (cyl's drum is the exemplar). Every new shape must declare `defH`; without it, tall shapes silently under-collide and flat ones over-collide.
- Plane labels are collision-checked at `write()` time: every `planeLabel()` registers its estimated screen quad (monospace em-box — 0.6em advance + letter-spacing, 0.75em ascent, 0.2em descent — pushed through the shear basis) and `checkLabels()` SAT-tests it against every unit's collision hull, every flow polyline, and every arrowhead triangle. Intersection is a hard error naming the label and the obstacle. Arrowheads are checked as polygons in their own right (and `autoLabel` avoids them the same way): the route check only covers the centerline, but the head flares 0.21 cells (~8px of ink) either side — a label can clear every route segment and still sit on the flare (azure_lob shipped its drum-pair AVAILABILITY SET caption reaching into the app→sql arrowhead until this check existed). Penetration under 3px is tolerated (the em-box overshoots real glyph ink by ~2px of advance/descender slack); anything deeper is real. Cylinders use a drum-tight hull (plate corners + drum screen box) instead of the full-footprint silhouette — the naive hull has ~28px of phantom air beside the drum that chips need but labels don't. This check caught two shipped collisions on its first run against existing layouts (a label tail 2px off a store corner, and a dashed flow running through "ENTRA ID"), both previously eyeballed as fine. Don't trust eyeballs at 1x for label clearance; the checker measures.
- Tier captions: prefer `autoLabel(txt, planeRect)` over hand-placed `planeLabel()` — call it AFTER `unit()`/`connect()`/`flow()` declarations (it can only avoid what already exists) and after earlier labels. It walks the plane's edges from the canonical top-left corner (0.3 inside, the exemplar convention), then a fallback ring 0.45 OUTSIDE the plane (the crowded-plane move: float the caption in adjacent air, as the gauntlet's DATA TIER does), taking the first spot with an honest 4px of clearance. It is deliberately stricter than `checkLabels()`: the checker's ~3px em-box slack plus unhulled outline strokes means a checker-legal spot can still put ink exactly on a plate line — autoLabel refused one such spot that had shipped-looking output. No clear spot is a hard error; `planeLabel()` remains the authored override for craft placements.
- Chip balloons are collision objects: every `chip()` registers its balloon footprint (number bubble + pointer tail) and `checkChips()` runs at `write()` time — a balloon overlapping a unit hull, a label, a flow route, another chip, or the canvas edge (8px margin) is a hard error. The chip's own target unit is exempt (the tip deliberately hugs its body). Point-target chips (`to = [gx, gy]`, the authored aim-into-exhibit-space escape hatch the glossary uses) are only checked against other chips and the canvas. `autoLabel` sees chips too, so call `annotations()`-adjacent `chip()`s before late labels if you author any directly.
- Prefer `annotate()` WITHOUT an approach point: the renderer casts rays through the target's body-hull centroid — screen-horizontal first (the balloon sits beside the solid where it reads best), then iso-grid diagonals, steeper angles, verticals last — simulates the exact balloon `chip()` would draw, and takes the first direction that clears every unit, label, flow, prior chip, the canvas, and the legend rail. No clear direction is a hard error naming the unit. Authored approach points remain the craft override; the guard still checks their balloons.
- Tier groups: prefer `group(origin, members, {cols, gap, pad})` over hand-placing each member — it packs whole-cell blocks row-major on the snapped grid through `unit()` (every placement guard applies; members keep their names for `connect()`/`annotate()`) and returns the enclosing rect, so the grouping sheet and caption are derived: `const r = group(...); S.push(plane(...r)); ... S.push(autoLabel("TIER", r))`. Blocks default 2x2 (`cells` per member overrides), `gap` is whole cells (default 1), `pad` is the plane margin (default 0.6, matching the exemplar's hand rects). Hand-placed `unit()` remains the override for irregular, painter's-order-tuned arrangements — packed grids read regular by design.
- Flow routing: prefer `connect(a, b)` with NO `via` — the router (`autoVia`, also exported) finds an orthogonal path on the Hanan grid of every unit's cell rect expanded by a 0.45-cell clearance margin, minimizing length then bends (0.75-cell penalty per bend), with exit/enter stubs stepping off the chosen edges — a full 1.0-cell stub when there is room, falling back to the bare clearance (the arrowhead is 0.42 cells long; a bend at 0.45 chokes the head with ~1px of visible shaft — hybrid's routed tunnel flow shipped that neck). Call `connect()` after every `unit()`/`group()` it must route around. A clear straight line stays the plain two-point segment (authored-layout byte-compat); running exactly on the clearance boundary is legal, so parallel lanes hug unit margins. Equal-cost detours break toward the screen-front lane (higher x+y) — a back lane runs behind the blocker's top faces and the flow disappears under isometric occlusion (the first demo render shipped this before the tie-bias). Two hard errors instead of bad ink: an exit edge flush against a neighbour (no stub room — e.g. interior edges of a `gap: 0` group; exit through an outside edge) and no route at all (walled-in target) — both say to add `via` waypoints. Authored `via` remains the craft override and is never second-guessed, only axis-lock-checked — give the head the same courtesy the router does: put the last authored waypoint ≥ 0.65 cells before the endpoint (azure_lob's gw jog at 0.5 read as a choked neck).
- Plane margins around unit cells must be ≥ 0.6 on any edge a flow crosses (0.6 is the exemplar convention and `group()`'s default `pad`): the arrowhead is 0.42 cells long and its base lands 0.42 outside the cell rect, so a 0.4-margin plane puts the head's base exactly ON the plane line (gauntlet, the autolabel demo, and hybrid's VNet all shipped this). This is enforced, not just documented: `checkPlanes()` runs at `write()` time and hard-errors when a head's base edge comes within 4px of a ground plane's outline. A line crossing MID-head stays legal (an intentional boundary crossing — hybrid's fw→app1 straddles the app-subnet line), and so does the TIP landing on a line (tips land on the target's cell rect; a plane edge flush with that rect is the exemplar's "arrow enters the tier" look, azure_lob's users→gw). Raised planes (z > 0) are depth-layered sheets and exempt — screen overlap there is occlusion, not touching. Labels are guarded too: a plane line cutting a chord longer than 1.8× the em-box's thickness through a label (i.e. running ALONG the ink, the desync defect) is a `checkLabels()` error, while the short chord of an iso-angle crossing stays legal (azure_lob's drum caption crosses the identity plane's top line by design); `autoLabel` applies the same test unpadded so placements survive `write()` without outlawing the canonical line-hugging caption spot. Wider margins beat smaller heads — head size is a legibility floor, not a tuning knob. Widen only the edges flows actually cross when a fixture depends on plane crowding (the autolabel demo's data tier stays tight on three sides so its caption still exercises the outside ring). And hand-authored planes must pass the SAME rect object to `plane()` and `autoLabel()` — duplicated literals desync silently, and a caption placed against a rect 0.2 cells smaller than the drawn plane put its ink exactly on the plane line (shipped in the autolabel demo when the margins were widened; `group()`-derived rects are immune by construction).
- Verify by rendering with headless Chromium (`--headless=new --screenshot=... --window-size=WxH file://...`) and reading the PNG. When a placement looks wrong, **measure pixels or render a debug frame** before "fixing" it — a correctly sheared decal was nearly broken twice on eyeball evidence.
